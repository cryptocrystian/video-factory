# Video Factory Model Benchmark Protocol v2

Status: **Canonical benchmark policy**
Supersedes: Model Benchmark Matrix v1

## 1. Purpose

Benchmarking exists to answer a specific production decision, not to create a generic “best model” ranking.

Every paid test must produce durable routing knowledge.

## 2. Four benchmark types

### CREATIVE
Question: which model produces the strongest documentary cinematography when allowed to interpret the same directing problem?

Rules:
- same canonical director brief
- **no shared starting image**
- model-native prompt compilation allowed
- production design may differ
- tests visual intelligence, taste, camera, motion, physics, and editability

### CONTINUITY
Question: which model best preserves an approved subject/environment while producing useful motion?

Rules:
- shared canonical reference is intentional
- exact reference roles declared
- similarity is expected
- tests identity, geometry, material, reference adherence, and motion quality

### SEQUENCE
Question: can the model produce multiple connected shots that cut together?

Rules:
- finalists only
- continuity package active
- tests angle variation, progression, temporal coherence, and editorial usefulness

### RELIABILITY
Question: what is the actual acceptance probability and retry economics for a known shot class?

Rules:
- repeated equivalent briefs
- used only after a route is creatively viable
- feeds cost-per-accepted-second

## 3. Preflight — mandatory before spend

A benchmark cannot start until all are written:

1. decision question
2. falsifiable hypothesis
3. benchmark type
4. canonical director brief version
5. candidate list
6. exact supported mode for each candidate
7. duration/resolution available for each
8. model-native adapter rules
9. scoring rubric
10. automatic reject conditions
11. blind labels
12. max attempts
13. max spend
14. result decision rule

Provider capabilities and pricing must be refreshed immediately before submission.

## 4. Same brief, not same literal prompt

Fair comparison means preserving **creative intent**, not forcing identical token strings.

Flow:

```
canonical director brief
→ selected model
→ model-native Prompt Compiler
→ exact submitted request
```

The compiler may express the same direction differently if the model/API requires it.

The canonical brief and exact submitted request are both retained.

## 5. First-pass attempt policy

- one paid attempt per candidate
- no hidden rerolls
- provider execution errors may be retried only if no charge/result was produced and policy permits
- model-quality failure is a result, not a reason to reroll

## 6. Review policy

### Native review
Inspect original output at native resolution and duration.

### Normalized review
Create a standardized comparison:
- common playback resolution
- common frame rate
- no score
- no SFX
- no post-processing that changes perceived model quality
- randomized labels

Do not hide native-resolution differences in the recorded telemetry.

### Blind first review
Where practical, reviewers score Clip A/B/C rather than model brands before identity reveal.

## 7. Creative-cinematography score

Default weights:

| Dimension | Weight |
|---|---:|
| Photographic / documentary realism | 25% |
| Camera physicality & cinematography | 20% |
| Temporal + geometry stability | 20% |
| Production design / visual taste | 15% |
| Story usefulness / editability | 10% |
| Canonical brief adherence | 10% |

Automatic reject can override weighted score.

## 8. Continuity score

Suggested dimensions:
- canonical identity preservation
- geometry/material preservation
- camera naturalism
- temporal stability
- physical plausibility
- useful variation from reference
- editability

## 9. Automatic rejection conditions

Material, unrepairable failures:
- geometry mutation
- subject identity mutation
- architecture mutation
- physically impossible camera
- broken horizon/orbital behavior
- nonsensical engineering
- severe temporal melting/flicker
- unintended text/logos
- reference bleed
- contradiction of provenance/evidence limits
- obvious “still image being pushed around” when true cinematography is required

## 10. Shot-class suite

Long-term suite:

- B01 speculative/frontier hero cinematography
- B02 industrial infrastructure
- B03 macro engineering
- B04 complex camera
- B05 recurring-subject continuity
- B06 real-world documentary environment/human motion
- B07 semantic scale transition
- B08 long stable take

Not every new model runs all eight immediately.

Use a funnel:
1. CREATIVE on representative hardest shot
2. CONTINUITY on finalists
3. SEQUENCE on top 1–2
4. RELIABILITY after a route becomes viable

## 11. Economics

Primary metric remains:

```
cost_per_accepted_second =
(total generation spend + attributable retries)
/ accepted final-screen seconds
```

Also track:
- first-pass acceptance
- eventual acceptance
- attempts per accepted shot
- cleanup burden
- continuity failure rate
- provider error rate
- latency

## 12. External skill recommendations

smixs/Kie/other model recommendations are recorded as **capability priors** only.

Routing changes require Video Factory evidence.

Latest model does not automatically displace a proven route.

## 13. B01 historical note

The first B01 run used one shared orbital keyframe across multiple models.

That run is retained as a **continuity datapoint**.

It is explicitly invalid as a creative-interpretation benchmark because the shared start frame constrained composition and production design.

Do not use it to decide which model has the strongest original cinematography.
